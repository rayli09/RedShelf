# RedShelf completion target

Match the observable behavior and layout of the Rouge Apple TV app, using native tvOS controls and materials on the current OS. Use original branding and artwork. The public App Store screenshots show recommendations, note details and comments, a video feed, live streams, search, profile and account switching, and settings. They do not establish every behavior or setting; inspect the real app or obtain additional references before claiming full parity.

## Acceptance

- A user can securely sign in, restore a session, sign out, and switch accounts. Report confirmation or verification failures accurately.
- Recommendations, videos, live streams, search, notes, comments, personal content, likes and favorites operate against real data with appropriate loading, empty, error and pagination states.
- Note images, video playback, navigation, scrolling, focus, remote control and account changes work end to end on a real Apple TV. Preserve the user's intended account and never expose credentials in logs.
- Match the reference layouts, typography, spacing, imagery proportions and interactions across supported screens, with native `TabView` and platform controls; verify with real-device comparisons rather than assuming pixel parity.
- Supply a correctly configured, layered tvOS app icon and validate it on the device home screen.
- Build and tests pass, including authentication state and parser tests. Any unavailable upstream feature or unverified behavior must be reported explicitly.

## Current state

The native navigation and layered icon are implemented. A tvOS simulator home screen displayed the icon and static Top Shelf artwork; physical Apple TV presentation has not been verified. A prior confirmed QR scan returned error `-1`; a subsequent RedNote scan established an account session and the user observed the recommendation feed on a physical Apple TV. Anonymous probes confirmed that Xiaohongshu and RedNote guest activation issue encrypted session keys; exchange, regional routing and account-key rotation have local mock coverage. QR generation and waiting have been tested anonymously; a subsequent mainland account also completed QR sign-in on the physical Apple TV. The account picker uses the Keychain vault to add or select accounts; its navigation and client transitions are tested with synthetic accounts, not real accounts. The regional vault uses a separate Keychain item; prior single-session and account-vault items are not deleted or imported. Server-side logout is not implemented. Profile, posted notes, likes, and collections use signed API calls with mock coverage but have not been tested with a real account. The recommendation feed follows the API cursor, with duplicate suppression and retry. The video tab filters this mixed feed for video notes and resolves each note's stream; it is not yet proven equivalent to Rouge's video recommendations. Live browsing is hidden from navigation at the user's request; the existing Xiaohongshu web square and public HLS code remains unverified against real responses and is unavailable for RedNote accounts. Simulator tests show a generated local clip advancing and a missing clip reporting failure, but neither proves real Xiaohongshu video playback. Pagination, search, note details, comments, and interactions have mock coverage only. Actual device playback and parity remain unverified. The app is not feature complete.
